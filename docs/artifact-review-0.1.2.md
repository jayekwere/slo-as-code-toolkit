## Issue found and fixed in 0.1.2

Rich's default SVG template embeds two CSS font-face declarations with four CDN URLs. Both stored SVGs contained these references, for eight total. Depending on the viewer and installed fonts, opening an SVG could fetch those fonts. This is an unnecessary external dependency for an offline artifact; no credential exposure or code execution was established.

The CLI now supplies an explicit SVG template using system fonts only. New regression tests exercise actual demo output and all checked-in SVG evidence, rejecting font-face/import declarations, non-fragment CSS URLs, active elements and linked resources. The two existing checked-in SVG copies have only their font-face declarations removed; terminal text and measurements are preserved. [Remediation hashes](../evidence/v0.1.2/svg-remediation.json) identify the original and sanitized copies.

Published v0.1.0/v0.1.1 archives, assets, tags and checksums remain unchanged. Their original SVG assets retain the old font declarations. Use the current sanitized repository copies or v0.1.2 exports when documents must open without external resource requests. System-font appearance can vary by viewer; the SVG text-length and layout attributes remain generated by Rich.
